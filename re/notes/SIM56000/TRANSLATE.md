# SIM56000: translation plan (10 independent work packages)

Everything needed to translate SIM56000.EXE (Motorola DSP56000 simulator 6.3.0, 01-15-1999, 2260 user
functions, 0x401000-0x4833fa; CRT from 0x483400) into portable C89 is on disk.  This file explains what exists,
the rules, and cuts the program into work packages that can be done in parallel.

## 0. What exists (all under C:\Arbeit\ASM56000)

| what | where |
|---|---|
| Ghidra export (all 2260 user functions incl. the ~660 that Ghidra did not find and that were created from the data tables) | `re/out/SIM56000/decomp.c`, `functions.txt`, `strings.txt`, `mod/<module>.c` (per corrected module) |
| corrected module map (65 modules, names describe the content; no `$Id` strings exist) | `re/notes/SIM56000/filemap.txt` (produced by `re/scripts/splitsim2.py`; the old `splitsim.py` ranges are wrong) |

| architecture/behaviour notes of the eight naming groups | `re/notes/SIM56000/{exec_a,exec_b,devinit_asm,cmd,coff_io,misc,cdb1,cdb2}.md`, `COMMANDS.md` (command set, oracle), `BRIEF.md` |

Regenerate everything after changing a names file or the spec:
`python re/scripts/gentab_sim.py` (data), `python re/scripts/genproto_sim.py` (prototypes),

and compare its output with `simverify.exp` (all 47437 scalar/string values of the generated data are checked this way;
last run: identical).

Compile check of the shared files: `gcc -std=c89 -pedantic -Wall -c src/sim56000/simd_dev.c` and
`m68k-atari-mintelf-gcc -std=c89 -pedantic -Wall -mshort -Isrc/sim56000 -c ...` (both clean).

## 1. Ground rules for all packages

* CLAUDE.md rules apply (ANSI C89 only, `long` for anything > 16 bit, never read/write structs raw, `& 0xffffffffUL` where the
  original wraps at 32 bit, file names 8.3 -> one source file per module of `filemap.txt`, e.g. `src/sim56000/core.c`,
  `decode.c`, `cmdh1.c`; use the names of the names files for functions and globals).  A comment at the top names the
  original binary and the module range.
* **No console API**.  The original is a Win32 full-screen console program; stdout/stdin redirection does nothing
  (`COMMANDS.md`).  The reconstruction has a plain line-oriented front end (stdin commands, stdout text) that produces the
  *session log transcript* (`log s file` ... `log off`) byte for byte.  Screen painting code (`console`, the cursor/window
  parts of `cmdloop`, `display_all` painter) is translated only as far as it affects the log text; the log is the oracle
  (`tests/sim56000/simtest.py`).
* Addresses in the notes/names are VAs of `re/bin/SIM56000.EXE`; Ghidra `local_NN` names are offset by 4 from the real ebp
  offsets; printf-style variadic arguments may be missing in `decomp.c` (check with `re/scripts/x86dis.py re/bin/SIM56000.EXE <start> <end>`).
* Originals reach state through raw offsets (`*(int *)(cur_sim + 0x3e78)`); use the members of `struct sim_state`,
  `struct dev_inst`, ... in `sim56000.h`.  If a member is missing, **add it to sim56000.h** (keep it the single source; announce
  changes in the package's commit message).  Struct layout is not the original's, so nothing may `memcpy` such structs or
  depend on offsets (the state file format is textual and independent of layout).
* Data tables are already there.  Use the generated symbols (`grep name src/sim56000/simdata.h`); do not retype tables.
  Function-pointer tables reference the original function names (`FUN_...`-free, from the names file); the translated
  functions must be **defined with exactly these names** so the tables link.  Tables that contain jump-table style code
  addresses were dropped (switch statements are translated as switches).
* Global variables in BSS are declared in `sim56000.h` (`cur_sim`, `cur_dev`, `cur_dtype`, `cur_itype`; others are named in
  the names files: add `extern` lines to the header as you need them; define each in its owning module).
* Known deviations of the generated data (details in `datamap.txt`, `gentab_sim.py`):
  * flex tables of the C expression lexer (`yycrank`, `yyvstop`, `yysvec`, `yymatch`) are in **index form**: `yysvec[i].stoff`
    is an index into `yycrank` in 2-byte units (may be negative; `YYNONE` = NULL), `stops` an index into `yyvstop` (-1 none) - the
    original stores pointers that reach below `yycrank`, which is not portable C.
  * element widths of auto-typed scalar tables were taken from the access widths seen in the machine code (`long`/`short`/
    `char`); check one access when a table looks wrong.  Record types of unnamed tables are `recNw_xxxxx` with fields `w0..`;
    curated types (`dev_type`, `periph_desc`, `group_def`, `reg_desc`, `mem_region`, `core_vtable`, `opclass_entry`, `mnem_entry`,
    `command_entry`) have named members.
  * five real function entry points lie inside the bodies of other Ghidra functions: `insn_class_h_42fa60`, `alu_h_432160`,
    `alu_h_4325f0`, `alu_h_432a70`, `cmd_display_h_450210` (they are separate functions in the C sources).
  * BSS pools that initialized data points to are `char bss_XXXXXX[]` in `simbss.c` (sizes are lower bounds); give them real types
    when the owning module is translated (e.g. `bss_4dbb08` = device instance table, `bss_4dba88` = sim block table).
  * The data files also contain the CRT's tables/strings (harmless; not needed).
* Build/test loop as in CLAUDE.md: `simtest.py check` runs the rebuilt `build/sim56000[.exe]` on the scripts and compares the
  files the original wrote (goldens in `tests/sim56000/golden/`).  Add sessions for your package (ideas below); goldens are
  made on Windows with `simtest.py gold NAME`.

## 2. Work packages

Sizes are the Ghidra C size of the module (functions / KB of `decomp.c`).  "Calls into" is the number of static call sites
from the package into others (from `functions.txt`), so you know which interfaces to stub (use `simproto.h`).

### P1 Foundation and expression evaluator  (269 fn, 296 KB)
Modules: `radix` 0x456f60 (device thunks, radix/value formatting, access-trace ring, `dsp_alloc`/`dsp_free` with mdisk spill),
`mdisk` 0x458060 (sparse memory with disk spill, swap files `<type><dev>.MEM`), `miscx` 0x45d120, `oprefs` 0x459030 (instruction
operand reference recording), `avltree` 0x46a700 (generic AVL tree), `memacc` 0x42c4c0 (memory/register access engine:
`mem_reg_read/write`, region lookup, OMR remap hooks), `expr` 0x459250 (simulator expression evaluator: `Expression result must be
integer`, `Divide by 0`), `cmdparse` 0x466950 (command argument syntax classifier, `parse_command_line`), `dispval` 0x43f010
(value formatting for watch, source-line helpers, `wait`).
Notes: misc.md (expression mode word, value node, radix, mdisk, expr), cdb1.md sec 6/7, cmd.md 6.4, devinit_asm.md 1.3/1.5.
Data: `fmt_tab_16/24/32(_nosym)`, `dec_split_16/24`, `mdisk_block_bytes`, `g_radix_names`, `bit_mask_tab`, `avl_cmp_tab`, `regsel_tab`, core_vtable_*.
Calls into: P6 (output/error text `out_text`, `sim_error`), P8, P2 (register lookup `periph_find_reg`).  Most called by everybody: do this first.
Tests: s01_basic (evaluate/radix), s05_mem, s06_regs.  New: s07_expr (all operators, `eval b/d/f/h/u`, floats `1.5e2`, `divide by 0`, `Expression result
must be integer`), s08_radix (`radix` per register/address block), s18_mdisk (56300-style huge memory spaces if a device type uses REGION_MDISK, `save s`
of mdisk state).

(instruction group statistics methods).
Notes: devinit_asm.md sections 1, 2 (decoder record DEC, appendix A/C tables), exec_a.md 5/7 (accumulator/CCR semantics, statistics).
Data: `opclass_table`, `dec_handlers`, `insn_exec/move/class/valid_handlers` + `*_records`, `alu_handlers`, `mnemonic_names`,
`keyed_dev_table`, `keygen_*` constants, register-id tables (`d_4bfc80`, `d_4bfd80`, `d_4c0*`).
Calls into: P4 (core register access `core_get_reg`, `core_store_reg_masked`), P6.  Only P4 calls back heavily.
Tests: s03_step (steps through p1), s06_regs; new: s19_alu (one small program per instruction family assembled with re/bin_ft/ASM56000.EXE

### P3 Assembler and disassembler  (289 fn, 222 KB)
Modules: `disfmt` 0x41fb70 (one formatter per opcode class producing token lists), `disasm` 0x423b10 (`disassemble`: tokens -> text,
display effective-address calculator), `asm` 0x4240d0 (inline assembler `asm_line`, `proc_instr`, operand parser, move-field
encoders, `enc_*`, `*_code`).  `asm` is the same source family as ASM56000's amode/encode/procop/procxy (different revision, see
devinit_asm.md Appendix B), so the ASM56000 reconstruction in `src/asm56000/` is a useful reference (do not
share code blindly: the revisions differ).
Notes: devinit_asm.md sections 2.3, 3, 4 (token strings, formatters, assembler), Appendix A/B.
Data: `dis_token_strings`, `dis_fmt_handlers`, `asm_mnem_table` (140 x {name, operand class, opcode base}), `asm_mnem_count`.
Calls into: P1 (expression evaluator for operands: 59 sites).  Independent of everything else once P1 exists.
Tests: s02_load (`disassemble p:$40..$48`); new: s07_asm (`asm` of every mnemonic form, `asm b`, errors `Unrecognized mnemonic`,
`* encoding failure`), s21_disasm (`disassemble` over a range holding every opcode class: assemble a test file with ASM56000, load
the .cld, disassemble p:0..).

### P4 Core CPU and peripherals A  (121 fn, 249 KB)
Modules: `core` 0x403ae0 (DSP core: register access, reset, `core_clock`, AGU, interrupts, memory bus), `emi1` 0x401a50 (56004 DRAM

Notes: exec_a.md (whole, sections 3-4 core register array/clock, 8 peripherals, 9 catalogue).  The 7-global "prologue" of every
method (exec_a 1.5) should become a `struct periph_ctx` passed explicitly (allowed; keep the generated method tables' signatures:
`void (*clock)(long dev, long grp)`-style wrappers named `<per>_m_clock` must exist).
Data: `dev_*` (12 device types), `periph_*`, `grpdef_*`, `regs_*`, `regions_*`, `core_vtable_*`, `emi1_timing_tab_*`, `agu_wrap_mask_tab`,
`emi2_burst_bits_tab*`.
Calls into: P7 (I/O channel sample/inject `io_*`), P1, P2.  Called by the run loop (P6 `sim_check_stop`/state cycle hooks).
Tests: s03_step, s04_break, s06_regs, s11_device; new: s22_core (interrupt vectors, `do`/`rep`, hardware stack, reset pin, `go`
with cycle counts: compare `display` and the `trace` output), s23_emi (device 56004/56007 + `change`/`display` of ebar/edrr registers and memory

## 3. Suggested order and integration points

1. **P1 + P6 first** (they are called by everything; P6 provides the transcript writer).  Milestone A: `simtest.py check s01_basic s13_path s14_help` pass.
2. P2 and P4 (with P5 as far as the default 56001 needs: host/ssi/sci/port/timer): Milestone B: `s03_step s05_mem s06_regs s11_device` pass, plus the
   ALU/single-step regression s19_alu.
3. P3 (assembler/disassembler): Milestone C: `s02_load s07_asm s21_disasm`.
4. P7 (commands and I/O channels): Milestone D: all command sessions.
5. P8, then P9 (C debugger), then P10 (profiler).  Milestone E: full command set, `load d`, C expressions, `log p`.
Stub strategy while a package is not finished: link against a generated stub file (the prototypes of the missing package from `simproto.h`, bodies that
`abort()`); the original function names are the link interface.  Each package should leave its `run_tests` lines in `tests/sim56000/run_tests.sh` (or extend `simtest.py`).

## 4. Known open points (from the naming pass)

* Semantics of several state-block members (`struct sim_state` has TBD counters, see cmd.md 7/8 and exec_a.md 1.4) - resolve from the fprintf/fscanf order of the state file.
* Field meaning of `reg_desc.f0c`, `periph_desc.f0c/f10/f24`, `mem_region.f14/f1c/f24/f28`, `dev_type.f10/f30/aux44/reserved` (all present and initialized by the generated data, meaning unknown).
* Call-graph node layout of the profiler (only accessed offsets known), `snap_*` kinds 3,4,6,7,10,11 (cdb2.md section 5).
* The generated data still contains many `recNw_xxxxx` records of unnamed tables (e.g. help text tables 0x4ad7e0.., register description tables `d_4b....`):
  name their types in `re/scripts/gentab_sim_spec.py` (`TYPESPEC`/`NAMES`) when the owning code is translated and re-run the generator - the header, the data and the verification
  program are regenerated consistently.
